BATCH REFRESH STRATEGY:
- Kalshi API has /markets endpoint that accepts multiple tickers
- Use cursor pagination to fetch all markets efficiently
- Rate limit: ~100ms between requests (already implemented)
- Estimate: ~1000 markets = ~10 pages = ~10 seconds

DATA FRESHNESS:
- Full sync: Run every 6-12 hours for all markets
- Quick refresh: User-triggered for visible markets only
- Candlesticks: Always fetch at runtime (not stored)
- Trades: Only fetch when needed for detection

SORTING & FILTERING:
- All done in SQL for performance
- Use prepared statements to prevent SQL injection
- Consider adding full-text search if needed

MIGRATION PATH:
1. Add last_fetched column (defaults to NULL for existing)
2. Run initial full sync to populate all markets
3. Update dashboard to use new endpoint
4. Keep old endpoint for backward compat (temporary)
5. Remove old endpoint after frontend migration
